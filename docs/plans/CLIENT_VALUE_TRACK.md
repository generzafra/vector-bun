# 1. Purpose

This document defines the **Vector Client Value & ROI Engine**.

Its purpose is to make the economic value of Vector visible, defensible, measurable, and understandable to the client.

Vector must not assume that a client will continue paying merely because:

- a website exists;
- social posts were published;
- SEO tasks were completed;
- AI generated content;
- campaigns ran;
- dashboards contain activity;
- the system appears sophisticated.

The client will eventually ask:

```text
What am I paying for?
What did Vector actually do?
What did it save me?
What business outcomes did it contribute to?
Would I be better off hiring people?
Would I be better off using an agency?
Could I simply do this myself with AI tools?
Is the service worth renewing?
```

Vector should be able to answer those questions using evidence.

The system therefore must connect:

```text
Vector activity
        ↓
measured output
        ↓
measured business outcome
        ↓
time / cost avoided where defensible
        ↓
commercial value
        ↓
confidence / evidence
        ↓
client-facing explanation
```

The governing principle is:

> **Vector must prove its value continuously rather than asking the client to remember why they bought it.**

# 2. Strategic Product Position

Vector is not primarily sold as:

- a cheaper web developer;
- an AI content generator;
- an SEO dashboard;
- a social scheduler;
- a graphic design generator;
- an agency reporting portal;
- a collection of SaaS subscriptions.

Vector is positioned as:

> **A Growth Operating System that gives a business the capabilities of an integrated digital growth department without requiring the client to assemble, coordinate, and supervise every specialist and tool individually.**

The value proposition should progressively become measurable through four dimensions:

```text
1. Business outcomes created or influenced
2. Work completed
3. Time and operational burden reduced
4. Replacement cost avoided
```

These dimensions are not interchangeable.

Vector must show them separately.

# 3. Core Commercial Problem

Modern AI dramatically lowers access to individual marketing capabilities.

A client can independently acquire:

- an AI assistant;
- website builders;
- design tools;
- SEO tools;
- analytics products;
- email platforms;
- social schedulers;
- image generators;
- automation tools.

Therefore Vector cannot rely on:

```text
"We use AI"
```

as a durable commercial advantage.

The DIY competitor is not one tool.

It is:

```text
AI assistant
+ website builder
+ design tool
+ SEO platform
+ email tool
+ social scheduler
+ analytics
+ automation
+ client labor
+ client expertise
+ client coordination
```

Vector must compete against the **total operating burden** of that stack.

# 4. The Vector Value Equation

Vector should calculate value using distinct components.

Recommended top-level model:

```text
VECTOR VALUE
=
Measured Business Value
+
Defensible Cost Avoidance
+
Defensible Time Value
+
Operational Value
+
Strategic / Asset Value
```

However, these components must not automatically be added into a single number.

Why:

- some categories may overlap;
- some are directly measured;
- some are benchmarked;
- some are estimated;
- some are qualitative;
- some may already be represented in revenue.

The client UX should prefer:

```text
Measured Results
Cost & Time Savings
Work Delivered
Strategic Progress
```

rather than one artificially precise number.

A composite value score may exist internally but must not imply financial certainty.

Examples:

- attributed sales;
- attributed bookings;
- attributed ecommerce revenue;
- qualified pipeline value;
- repeat purchase value where available.

This is the strongest category when data is reliable.

Example:

```text

High

```

Never imply Vector caused all attributed revenue.

Preferred language:

```text
Attributed to Vector-managed acquisition paths
```

or:

```text
Associated with Vector-managed campaigns
```

depending on evidence.

---

## 7.2 Conversion Improvement Value

Examples:

- more leads from the same traffic;
- more qualified leads;
- improved booking completion;
- improved checkout rate;
- reduced abandonment;
- improved lead-to-sale rate.

Possible value estimation:

```text
incremental_conversions
×
verified_average_value
```

Only calculate when:

- baseline is valid;
- comparison period is appropriate;
- measurement is stable;
- no major uncontrolled factor makes the estimate misleading.

Tag result as:

```text
measured
estimated_incremental
```

as applicable.

---

## 7.3 Replacement-Cost Value

Replacement-cost value estimates what it might reasonably cost the client to reproduce comparable work through:

- freelancers;
- internal staff;
- specialist vendors;
- an agency;
- external tools.

This is a benchmark.

It is not revenue.

Example:

```text
This month Vector delivered:

Website optimization
SEO monitoring
12 social assets
8 social posts
2 campaign landing pages
1 email sequence
analytics reporting

Estimated external replacement range:
₱85,000–₱165,000

Vector plan:
₱35,000
```

The range must be based on a configured benchmark profile.

Do not display a fake universal market rate.

---

## 7.4 Time-Saved Value

Measure client or operator effort reduced.

Examples:

- content planning;
- campaign assembly;
- reporting;
- SEO review;
- social scheduling;
- page production;
- creative resizing;
- analytics review;
- lead routing;
- repetitive approvals.

Possible client-facing representation:

```text
Estimated owner/team time avoided:
22–34 hours
```

Financial conversion should be optional.

If client chooses an hourly value:

```text
time_value = estimated_hours_saved × client_defined_hourly_value
```

Do not assume an executive's hourly value without explicit configuration.

Examples:

- fewer missed leads;
- fewer stale campaigns;
- fewer broken integrations;

Operational value may be represented using non-financial metrics.

# 8. Evidence Classes

Every value claim requires an evidence class.

Recommended:

```text
verified
measured
provider_reported
client_confirmed
modeled
estimated
benchmark
inferred
qualitative
unknown
```

Definitions:

## Verified

Confirmed by an authoritative business source.

Examples:

- CRM won deal;
- ecommerce transaction;
- client-confirmed sale.

## Measured

Directly measured by Vector.

Examples:

- form submission;
- page conversion;
- campaign click.

## Provider Reported

Reported by approved external provider.

Examples:

- Search Console click;
- Meta campaign result;
- email provider delivery.

## Client Confirmed

Confirmed manually by authorized client user.

## Modeled

Calculated using a defined model with known inputs.

## Estimated

Reasonable approximation with uncertainty.

## Benchmark

Derived from market or internal comparison ranges.

## Inferred

Analytical interpretation rather than directly measured fact.

## Qualitative

Useful but non-numeric.

## Unknown

Not enough evidence.

Client UX must never visually present:

```text
benchmark
```

with the same certainty as:

```text
verified
```

# 10. No Double Counting Rule

This Client Value track must aggressively prevent inflated ROI.

Example:

If conversion improvement created an estimated:

```text
₱100,000 incremental revenue
```

and that revenue is already included in:

```text
₱400,000 attributed revenue
```

do not add both and display:

```text
₱500,000 total value
```

unless the categories are provably distinct.

Potential overlap matrix:

| Category A         | Category B          | Default                  |
| ------------------ | ------------------- | ------------------------ |
| Attributed revenue | Incremental revenue | Do not sum automatically |
| Replacement cost   | Time value          | Potential overlap        |
| Replacement cost   | Tool savings        | Potential overlap        |
| Revenue            | Replacement cost    | Usually distinct         |
| Revenue            | Operational savings | Usually distinct         |
| Protected value    | Revenue             | Case-specific            |

Create a `value_overlap_policy`.

---

# 11. No Fake ROI Rule

The system must not display:

```text
Vector generated 12× ROI
```

because it published activity.

A client-facing ROI number requires a defined numerator and denominator.

Recommended:

```text
roi = (verified_or_approved_value - vector_fees) / vector_fees
```

But use only approved value components.

Examples:

## Revenue ROI

```text
(attributed_revenue - vector_fees) / vector_fees
```

This is not the same as incremental profit ROI.

Label it clearly.

## Incremental Value ROI

```text
estimated_incremental_value / vector_fees
```

if defensible.

## Cost-Avoidance Ratio

```text
replacement_cost_estimate / vector_fees
```

Do not call this revenue ROI.

## Doc 25 — Glossary

Add:

**Attributed Revenue**  
Revenue linked to a Vector-managed acquisition or conversion path under the configured attribution method. Attribution does not necessarily establish sole causation.

**Replacement Cost**  
A benchmarked estimate of the external cost required to reproduce a comparable set of delivered services.

**Time Savings**  
Estimated reduction in human effort caused by Vector automation or integration, calculated using an approved benchmark or client baseline.

**Revenue-to-Fee Ratio**  
Attributed revenue divided by the Vector fee for the same period. It is not profit ROI.

**Value Maturity**  
The level of evidence available to support a client's value reporting, from activity-only to revenue-linked and incremental measurement.
